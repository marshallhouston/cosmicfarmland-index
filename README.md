# cosmicfarmland-index

The apex landing for **cosmicfarmland.wtf** — routes to my apps and catalogs the
skills, commands, and plugins I build them with.

- Apps live on subdomains (`<slug>.cosmicfarmland.wtf`); this is the apex index.
- `data/apps.json` — hand-curated app list (live + coming-soon).
- `data/catalog.json` — generated from the cosmic-farmland plugin repo.

## Develop
```
bun install
bun run dev        # vite dev server
bun run gen        # regenerate data/catalog.json from ../cosmic-farmland
bun run build      # static SPA -> dist/
bun run start      # serve dist/ + /api/health (prod, Bun)
bun test           # server contract tests (build first: they read dist/)
```

## Agent surface

The index is a client-rendered SPA, so everything an agent needs is published
without JavaScript:

- `public/llms.txt` and `public/index.md` — the whole farm in one file,
  including a **when to use this site** section. Generated by
  `scripts/gen-seo.mjs`, never hand-edited.
- `public/sitemap.xml` — indexable urls with `lastmod` from the build commit.
- `content/*.md` — the about, contact and privacy pages, authored once as
  markdown and published as both `public/<slug>.html` (Grayton Beach skin, via
  `scripts/md-page.mjs`) and `public/<slug>.md`, so the two cannot drift. Edit
  the markdown, run `bun run gen`, never the generated html.
- `scripts/seo-fragment.mjs` injects a plain-HTML mirror of the farm into
  `#root` at build time; React clears it on mount.
- `public/<32-hex>.txt` + `scripts/indexnow.mjs` — IndexNow ownership key and
  the ping, submitted to Bing, DuckDuckGo, Yandex and Seznam. **Automatic**:
  `server.mjs` pings on boot when the sitemap it is serving was built today, so
  every deploy submits itself and a plain restart stays quiet. `node
  scripts/indexnow.mjs` runs it by hand. Google does not take IndexNow: its
  sitemap is submitted once, manually, in Search Console.
- `server.mjs` negotiates on `Accept` (acceptmarkdown.com): `text/markdown`
  gets the `.md` twin with `Vary: Accept, Accept-Encoding`, a markdown-only
  client on a path with no twin gets 406, and unknown paths get a real 404 with
  a markdown body pointing at llms.txt and the sitemap. `tests/server.test.mjs`
  holds that contract.
- Every page answers at one url: `server.mjs` 301s `/about.html` to `/about`
  and `/index.html` to `/`, and each page declares its pretty url as canonical.
  `tests/seo.test.mjs` holds that contract, plus the sitemap invariant (every
  url 200, self-canonical, indexable). See `SEO-AUDIT.md`.

## Design system

**`public/sheet.css` is the sheet** — the design system for this domain. A
herbarium sheet: cream card stock to all four edges with no frame, black ink,
each entry mounted as a print card inside a ruled cell. Tokens, the paper, the
ruled grid, the print card and the accession label, in one plain stylesheet with
no build step. Any page can adopt it:

```html
<link rel="stylesheet" href="https://cosmicfarmland.wtf/sheet.css">
<html data-theme="dark">   <!-- or "light"; the viewer's system is the default -->
```

The SPA imports the same file from `src/index.css`, so there is one source of
truth. `golf-skin.css` and `city-am-skin.css` sit on top of it and only map the
vault pages' own token names and style their components. `DESIGN.md` is the
document.

It replaced Grayton Beach, which was sampled off a photograph of a hand-painted
welcome sign. That system is archived rather than deleted: `/grayton` is still
up as a record of what the site used to be, `public/grayton.css` is kept for
that one page, and nothing else links it.

`design-explore/` holds the work that produced the sheet, and its rules are
binding: `DIRECTION.md` is the brief, `TASTE.md` is the owner's own reactions
and wins over everything, `CRITIC.md` lists what is settled and must not be
re-argued, `critiques/` logs every critic run, `rejected/` keeps every variant
that lost.

## Deploy
Railway, single-stage Bun Docker. Health: `/api/health`. Point apex `@` + `www`
(Cloudflare) at the service.

## Stack
